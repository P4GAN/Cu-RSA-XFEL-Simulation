# Electron-impact ionisation: implementation plan

Companion to `docs/theory-eii-and-free-electrons.md` (Part VII; "VII §x" below). Depends on steps 0–2
of `docs/middlemen-implementation-plan.md`: M-shell EII feeds the middleman pool, and the population
bookkeeping built there (`untracked_out`, the trace check) is what EII's electron production reads.
Nothing here has been implemented yet.

Expected payoff at 8048 eV (estimator, VII §6.4): L-shell EII makes the 20–30 µJ dip 0.005–0.009
deeper (+10–20% on the ln-dip). M-shell EII mostly reshapes the dip (broadening, threshold-like wings)
and is bracketed between 0 and the atomic BCF rate.

---

## Step 1 — parameters (`xatom/eii_tools.py`, new)

Pure Python plus the existing XATOM parsers, no new XATOM run modes:

| Function | What it returns |
|---|---|
| `bcf_cross_section_nm2(E_eV, I_eV, zeta, n, l, R0=1.0)` | Eq. VII.1. Validated against the slide: 1/(nσv) at 7 keV = 65/11/2.3/0.21 fs for 2p₃/₂/3s/3p/3d |
| `stopping_power_eV_nm(E_eV)` | Joy–Luo modified Bethe for Cu (J = 322 eV, k = 0.83) |
| `binding_energies(hole_config='')` | `parse_orbital_energies_rel(run_xatom_cached(hole_config))` → {subshell: (I, ζ)} |
| `eii_ladder_parameters(n_groups=6, E_top=8100, E_bottom=30, targets=('', '3d0,2', ...))` | group edges and centres, `k_down_fs[g]` (Eq. VII.3), and `rate_fs[target][subshell][g] = n σ v` at one electron per atom |
| `birth_groups()` | group index per production channel (photo-2s 6949, photo-2p 7076/7096, photo-M 7.9–8.0 keV, KLL 6.9–7.2 keV, LMM ~870, L₁ CK ~60, M-cascade ~30 eV) |

Plus a `xatom/print_eii_parameters.py` CLI that writes the YAML block, the same pattern as
`print_satellite_parameters.py`. The first smoke test is the single-electron yield test in the
validation section (targets: VII §5 table).

**Config block:**

```yaml
use_eii: true
eii:
  groups_eV: [7600, 4300, 2400, 1350, 760, 240]     # illustrative only; generated by print_eii_parameters.py
  k_down_fs: [...]                                  # generated, Eq. VII.3
  rate_fs:                                          # n*sigma*v at n_e/n = 1, per group; generated
    ground: {2p3/2: [...], 2p1/2: [...], 2s: [...], 3s: [...], 3p: [...], 3d: [...]}
  birth_group: {photo: 0, KLL: 0, LMM: 4, CK_L1: 5, M_cascade: 5}
  spatial_factor: 0.5          # fraction of EII events that stay in the pixel/beam (VII §6.1); 1 = no transport loss
  M_shell_scale: 1.0           # 0..1: localisation of valence-3d EII in the metal (VII §6.3); bracket both ends
  thermal_bath: false          # n_th only needed for collisional M-shell ionisation by the cold end
```

## Step 2 — state

`rho_e_gxy`: shape (G, x, y), float, dimensionless (electrons per atom), one row per group. Optional:
`rho_eth_xy` and `E_eth_xy` for the thermal bath. These are added exactly like `rho_2s_xy`:
initialised to 0 in `init_n_level_3D` and in the lean-mode ICs, stepped by one extra RK4 call per `it`
from pre-update values, and kept in 2-slot buffers in lean mode only if something downstream needs
their history (nothing does, so lean mode can keep only the current slice).

## Step 3 — production terms (every existing rate that ejects an electron)

All of these are already computed, so the job is bookkeeping. Put them in one function,
`Model.electron_production_gxy(X, pops, J−, J+)`, returning (G, x, y):

| Existing term (where it lives now) | Electron | Group |
|---|---|---|
| ground PI, all `S_ground_Fi` columns (`MB_ground_regular`) | photoelectron | `photo` |
| ion PI: `S_ion_Fi` (base, satellites), `S_2s_F`, middleman PI (Part VI step 1) | photoelectron | `photo` |
| untracked Auger outflow of L3/L2 manifolds (`untracked_out`, Part VI step 1) | L-MM Auger | `LMM` |
| untracked non-radiative outflow of K manifolds | KLL (≈0.75 of it) + KLM/KMM | `KLL` / `LMM` |
| 2s CK feeds (`Gamma_A_2s*`, `Gamma_A_2s_to_L2*`) | CK electron | `CK_L1` |
| 2s L₁-MM remainder | ~1 keV Auger | `LMM` |
| double-sat `feed_from` (3p± super-CK) | ~12 eV electron | `M_cascade` |
| middleman cascade (per the cascade matrix: electrons per step, from Part VI step 3) | 10–40 eV | `M_cascade` |
| every EII event (step 4) | secondary | lowest group |

Electron-number check: Σ(all rates above) = d/dt(Σ_g n_g + n_th) + (escape, if modelled). Assert it
in a debug run.

## Step 4 — EII sinks

Rate per target atom from group g: `R_i = spatial_factor · n_g · rate_fs[target][i][g]`, with
`M_shell_scale` multiplying the M-shell entries.

| Target | Subshell | Destination | Sublevels |
|---|---|---|---|
| ground | 2p₃/₂ / 2p₁/₂ | base L3 / L2 diagonal | even (isotropic projectile) |
| ground | 2s | `rho_2s` (then the existing CK feeds) | — |
| ground | 3d / 3p / 3s | middleman pool: n → n+1 / n+2 / n+3 via the cascade matrix | — |
| middleman M_n | 2p / 2s | the satellite target of n (same routing as middleman PI, Part VI step 2) | even |
| middleman M_n | M shell | M_{n+1…} | — |
| base or satellite with a core hole | 3d / 3p | next satellite tier (base L3 → `3d±` L3k; `3d±` → double) | **preserve** the core-hole sublevel (the stash's Phase-A shape, `feed[i] += R · rho_ii`) |
| core-holed | 2p / 2s | 2p⁻², … | skip (0.5% of holes, resonant at +35 eV) |

Losses mirror the gains, so ground/pool/base populations lose what they feed. That is required for
the Part VI trace check to keep passing.

Implementation shape: the ground and middleman sinks go into `MB_ground_regular`,
`MB_middleman_regular` and `feed_diag_base_block`, as extra terms with the same form as the `S·J·ρ`
pump terms, with `J` replaced by the group-summed EII rate. The core-holed sink goes into
`feed_diag_satellite_block` next to the existing `sigma_Ka1_from_2p` loop.

## Step 5 — ladder kinetics

`Model.MB_electron_ladder_regular(t, rho_e_gxy, params)`:

```
d n_g/dt = production_g − k_down[g] n_g + k_down[g-1] n_{g-1}     (g > 0)
d n_0/dt = production_0 − k_down[0] n_0
(last group → n_th, or dropped when thermal_bath is off)
```

The primary loses energy only through `k_down` (Eq. VII.3), whose stopping power already includes the
energy spent on ionisation. There is no separate depletion term and no τ_th. The largest rate is
k_down for the lowest group (~30 fs⁻¹), so dt = 0.00375 fs (the production grid) is ample. The
largest EII rate is the 3d one, ≈1.4 fs⁻¹ per atom at 20 µJ (VII §6.3), also fine.

---

## Step 6 (optional) — transport

Only if `spatial_factor` turns out to matter. A per-group transverse diffusion,
`D_g ∇²_⊥ n_g` with `D_g = v_g λ_tr,g / 3` (≈1700 nm²/fs at 7 keV, ≈300 nm²/fs at 2 keV), on the
existing (x, y) grid (pitch ~36 nm). Use explicit finite differences with sub-stepping inside the
`it` step, or an FFT diffusion kernel reusing `Optics.my_fft`. Replaces `spatial_factor`. Neglect z
transport: the foil is 20 µm and the ranges are < 0.4 µm.

## Validation

1. **Reduction:** `use_eii: false` gives bit-for-bit the Part VI result. `rate_fs = 0` with
   `use_eii: true` gives the same populations while the ladder still fills (tests the production
   bookkeeping in isolation).
2. **Single-electron yields:** inject n₀ = 1 into one pixel of a cold, field-free grid and integrate.
   The 2p₃/₂/2p₁/₂/2s/3p/3d counts should match VII §5 (0.109/0.053/0.035/4.7/63) to within the
   6-group discretisation error (≤4%), and the time to leave the keV range should be ≈7.5 fs.
3. **Electron number** (step 3) and **energy** (Σ birth energy = Σ_g n_g E_g + Σ binding spent +
   bath) to RK4 accuracy.
4. **Estimator cross-check:** V4 and V4b of `toy_rsa.py` predict ΔT(8048, 20 µJ) = −0.005
   (spatial_factor 0.5) and −0.009 (1.0) relative to Part VI's step-0 baseline.
5. **Cluster provenance guard** (as in the Part VI plan), since `use_eii` is a new flag.

## Cost

G = 6 scalars per pixel, plus a production function built from quantities already on hand. Well
under 10% of runtime. The transport option adds one 2D diffusion per group per `it`: small if FFT-based.

## Order of work

Step 1 (parameters and single-electron yield test offline) → steps 2, 3 and 5 with L-shell sinks only
(the part that changes the dip depth) → run the 5/20/30 µJ mono points at `spatial_factor` 0.5 and 1
→ add M-shell sinks with `M_shell_scale` = 0 and 1 → compare the *shape* against slides 5–6 (blue-side
onset, width at 1 µJ) → step 6 only if the spatial factor bracket matters.
